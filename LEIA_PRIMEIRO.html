Chacobras · Fluxo de Caixa

Versão 1.0 · 21/10/2026 · Guia de publicação e atualização.

O que está pronto

Aplicativo estático para GitHub Pages, configurado para o Firebase ruralnutricao-7bf79. Inclui login Google, premissas editáveis, cronograma de dívidas, cálculo automático, detalhamento das receitas e dos custos, conferências, exportação/importação JSON, impressão e histórico compartilhado.

Os arquivos públicos não contêm os dados financeiros. Eles são importados no primeiro acesso pelo arquivo privado Chacobras_Dados_Iniciais.json.

A conexão autenticada com o seu Firebase e o endereço publicado no GitHub ainda precisam da configuração abaixo. Não foram testados com a sua conta. As regras devem ser publicadas antes de salvar dados.

1. Enviar o aplicativo ao GitHub

  1. Baixe e extraia Chacobras_GitHub.zip no computador.
  2. Abra o repositório ronei-dotcom/chacobras-fluxo-caixa.
  3. Na aba Code, escolha Add file → Upload files.
  4. Arraste os arquivos extraídos para a página. O index.html deve ficar na raiz, ao lado do README, e não dentro de uma subpasta.
  5. Clique em Commit changes. Não envie o ZIP fechado.
  6. Em Settings → Pages, mantenha Deploy from a branch → main → / (root). Aguarde a publicação e use o botão Visit site.

Envie somente o conteúdo de Chacobras_GitHub.zip. Não envie o JSON inicial, a planilha, os backups ou relatórios financeiros ao repositório público.

O código é HTML/CSS/JavaScript e não precisa executar npm install firebase. As bibliotecas de autenticação e banco são carregadas do CDN oficial do Firebase ao entrar com Google.

2. Autorizar o domínio do GitHub no Google

  1. Abra o Firebase, projeto ruralnutricao-7bf79.
  2. Em Authentication → Configurações → Domínios autorizados, clique em adicionar domínio.
  3. Informe somente ronei-dotcom.github.io, sem https e sem caminho.
  4. Confira que o provedor Google está ativado em Método de login.

Use o e-mail roneizoo@gmail.com para o primeiro acesso. Ele é o administrador definido nesta versão.

3. Publicar as regras de acesso do Firestore

Abra Firestore Database → Regras, no mesmo projeto novo. Substitua o texto pelas regras completas abaixo e clique em Publicar. Não use modo de teste.

Estas regras liberam apenas o administrador e as contas que ele autorizar dentro do aplicativo. O histórico é imutável e cada salvamento é vinculado à respectiva versão. A primeira carga de dados é exclusiva do administrador.

rules_version = '2';
service cloud.firestore {
 match /databases/{database}/documents {
  function googleUser() {
   return request.auth != null && request.auth.token.email_verified == true
     && request.auth.token.firebase.sign_in_provider == 'google.com';
  }
  function owner() {return googleUser() && request.auth.token.email == 'roneizoo@gmail.com';}
  function role() {
   return get(/databases/$(database)/documents/chacobrasMembers/$(request.auth.token.email)).data.role;
  }
  function reader() {return googleUser() && (owner() || role() in ['editor','viewer']);}
  function writer() {return googleUser() && (owner() || role() == 'editor');}
  function validBody(d) {
   return d.keys().hasAll(['payload','revision','updatedBy','updatedAt','lastChangeId'])
    && d.keys().hasOnly(['payload','revision','updatedBy','updatedAt','lastChangeId'])
    && d.payload is string && d.payload.size() <= 250000
    && d.revision is int && d.revision > 0
    && d.updatedBy == request.auth.token.email && d.updatedAt == request.time
    && d.lastChangeId is string && d.lastChangeId.matches('^[A-Za-z0-9]{20}$');
  }
  function historyMatches(d) {
   return getAfter(/databases/$(database)/documents/chacobrasFlow/main/revisions/$(d.lastChangeId)).data == d;
  }
  match /chacobrasMembers/{email} {
   allow get: if googleUser() && (owner() || request.auth.token.email == email);
   allow list: if owner();
   allow create, update: if owner() && email != 'roneizoo@gmail.com'
     && email.matches('^[^/@ ]+@[^/@ ]+[.][^/@ ]+$')
     && request.resource.data.keys().hasOnly(['role'])
     && request.resource.data.role in ['editor','viewer','disabled'];
   allow delete: if false;
  }
  match /chacobrasFlow/main {
   allow read: if reader();
   allow create: if owner() && validBody(request.resource.data)
     && request.resource.data.revision == 1 && historyMatches(request.resource.data);
   allow update: if writer() && validBody(request.resource.data)
     && request.resource.data.revision == resource.data.revision + 1
     && request.resource.data.lastChangeId != resource.data.lastChangeId
     && historyMatches(request.resource.data);
   allow delete: if false;
   match /revisions/{id} {
    allow read: if reader();
    allow create: if writer() && validBody(request.resource.data)
     && id == request.resource.data.lastChangeId
     && getAfter(/databases/$(database)/documents/chacobrasFlow/main).data == request.resource.data;
    allow update, delete: if false;
   }
  }
  match /{document=**} {allow read, write: if false;}
 }
}

Como fazer as atualizações

  • Premissas: altere preços, quantidades, ganhos de peso e investimentos. As taxas só substituem os anos de 2027 a 2035 ao clicar em Projetar série; o sistema pede confirmação antes de sobrescrever a série.
  • Dívidas: adicione banco, contrato, data, principal e juros. Cada parcela entra no seu ano. Parcelas posteriores a 2035 ficam no cadastro e fora do horizonte. Não separe principal e juros da terra: mantenha o total em compra de estância conforme combinado.
  • Salvar: clique em Salvar no Firebase depois das alterações. A outra pessoa recebe a versão quando estiver conectada. O aplicativo não grava automaticamente a cada digitação.
  • Edição simultânea: se alguém salvar enquanto você edita, o sistema bloqueia a substituição da versão nova. Baixe seu backup antes de carregar a versão compartilhada e reaplique suas alterações.
  • Histórico: cada salvamento registra autor e horário no servidor. É possível baixar uma das últimas 20 versões ou carregá-la para revisão. Para restaurar definitivamente, salve a versão revisada; o histórico anterior permanece.
  • Backup: baixe o JSON antes de mudanças importantes. O backup contém dados financeiros e deve ficar fora do GitHub.
  • Linhas zeradas: ocultadas automaticamente no fluxo e no detalhamento quando todos os dez anos são zero. Totais permanecem visíveis. O botão Mostrar linhas zeradas vale só para a tela: o relatório impresso sempre oculta as linhas zeradas.
  • Relatórios: Imprimir fluxo gera duas páginas de cinco anos cada. Fluxo + detalhamento gera seis. Na janela de impressão, escolha A4, paisagem, e desative cabeçalhos e rodapés do navegador.

No modo Abrir arquivo local, nada é sincronizado. Baixe um JSON antes de fechar. Depois de carregar o site, o cálculo local não depende do Firebase; não é um aplicativo instalável com cache offline garantido.

Conferências e limites

Os 700 valores do bloco de cálculo de 2026–2035 coincidiram com o Excel de referência. Foram conferidos os efeitos das parcelas de Cerro Memby, de dívidas bancárias, das receitas, da projeção por taxas e da conciliação do caixa e do rebanho. A importação, a edição e o backup foram exercitados no navegador.

As regras e o fluxo de login não foram validados no seu projeto ao vivo. A implantação exige o primeiro acesso e salvamento acima. A impressão foi verificada pela montagem das seis páginas no navegador; valide a prévia física no navegador que você usa antes de enviar ao banco.

O sistema mantém o horizonte 2026–2035 e a regra de compra com ciclo de 12 a 24 meses do modelo. Não calcula TIR ou CAGR e não inclui o bloco patrimonial no material bancário. As premissas de patrimônio são preservadas no cadastro e no JSON para uso interno.

Os avisos de juros zerados refletem os dados de origem, sem estimar juros que não foram informados.

Se algo não funcionar

  • Site só mostra README: confirme que index.html está na raiz da branch main.
  • Domínio não autorizado: adicione ronei-dotcom.github.io no Authentication.
  • Acesso negado: confira a conta usada, as regras publicadas e a liberação em Acessos.
  • Pop-up bloqueado: libere o pop-up do Google no navegador.
  • Salvar não conclui: baixe um backup e confira a internet. Não feche a página com alterações pendentes.
